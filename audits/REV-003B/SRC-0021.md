## Extraction summary

The runtime input is `(q,d,h,t,a)`: user query, tool documentation, prior calls/outcomes, selected tool, and parameter assignment; the conceptual guard returns `Aligned` or `Misaligned` (§4.2.1, p. 4). Table 1 defines `SpecifiedBy`, `ContributeTo`, `RelevantTo`, `AppearIn`, `DerivedFrom`, and `CanAddress` relations (p. 5). Tool-level alignment requires a documented tool relevant to a subtask contributing to the query; parameter-level alignment requires derivable parameters grounded in contextual evidence and able to address the subtask; interpretation-level alignment requires that context not leave multiple distinct provenance-admissible actions (§§4.2.3–4.2.5, pp. 4–5).

ProvenanceGuard implements these checks sequentially. It first filters for environment-changing tools and blocks if tool relevance is not established; next it identifies derivable (not generative) parameters and blocks if derivation or suitability is unsupported; finally, without revealing the proposed action to the checker, it blocks when multiple provenance-admissible alternatives exist (§§4.3.1–4.3.3, pp. 5–6). The surrounding workflow says a block may instead request user confirmation or clarification (§2.1, pp. 2–3), but the implemented pipeline's reported output is binary block/allow and the full text does not specify an appeal, override, or evidence-correction protocol.

WorkBench contributes 62 misaligned and 326 task-successful environment-changing traces; its ground-truth sequences do not make the latter necessarily aligned under underspecification. The Agent-SafetyBench subset was generated into 188 traces and independently annotated by two authors, with disagreements resolved and five cases removed, yielding 148 misaligned and 35 aligned traces (`κ=0.85`) (§5.1, pp. 6–7). Because neither benchmark supplies plans, GPT-5 reconstructs a subtask at each decision point (§5.1.3, p. 7). Baselines are DirectPrompt (LLM-as-judge) and ProvePrompt (single-step provenance prompt); ten LLM backbones are tested five times (§§5.2–5.4, p. 7). Metrics are error/false-negative rate on misaligned traces and intervention rate on aligned or task-successful traces (§5.4, pp. 7–8). Mean error falls from 42.9% to 1.8% on Agent-SafetyBench and 32.1% to 17.3% on WorkBench; WorkBench task-successful intervention falls from 30.5% to 12.8%, while Agent-SafetyBench aligned-trace interventions average 14.3% versus 10.1% baseline, with seven of eight observed increases not significant (§§6.1–6.2, pp. 8–10).

## D. Boundary verdict

1. **Demonstrated mechanism:** an implemented, evaluated, pre-execution allow/block pipeline that ties tool, derivable parameter, and interpretation choice to explicit contextual provenance.
2. **PCC coverage:** strongest for PCC-C01, PCC-C04, PCC-C05, PCC-C07, and PCC-C08; the environment-changing gate overlaps PCC-C06.
3. **Unlocated or outside scope:** multi-human actor-indexed public/shared state, participant acceptance, organizational authority, governed persistent artifact/workflow promotion, participant correction of evidence, and override/reversal/appeal.
4. **Necessity to PCC:** these links are necessary to the proposed combination because PCC's target is promotion into a role- and artifact-governed shared action state with a human-contestable record, not solely one agent's tool call.
5. **Verdict:** **possible near-equivalent (high confidence for the traceable-evidence gate; high confidence that the audited text is not a complete PCC equivalent)**. It is the strongest REV-003B comparator for traceable-evidence action gating, but the multi-actor public-state, role-governance, and human-contestation links were not located.
